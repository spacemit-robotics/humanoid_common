# 本机标准手柄客户端

`hmi_gamepad` 是与 terminal/web/Android 并列的 operator 客户端，不是电机驱动。
读取 Linux evdev，通过本机 HMI 连接文件认证，不依赖无线网络。
普通调度线程处理输入和回执，不占用 driver/control/RL 的实时线程。

机型 YAML `operator_gamepad` 声明 enabled、device、vendor、product、layout、bindings；
支持当前已验证的 `ds4_generic` 和标准 `xbox` 布局。DS4 通用布局严格检查
hid-generic 驱动，避免加载 hid-playstation 后错误解释相同 VID/PID。
轴范围读取 EVIOCGABS，不假设一定是 0..255 或 int16；方向固定为机器人 X 前、Y 左、yaw 左转为正。
输入读取为 O_RDONLY、不使用 EVIOCGRAB，不修改接收器固件或配对状态。
默认不写 HID；显式配置可选 `rumble` 后，仅独立反馈线程写入震动报告。

每条 binding 支持一个键或两个不同按键，operation 为 control/state/policy/preset/action/cancel/ack。
control 切换控制权持有状态；其余操作复用现有 HMI 校验和控制链路。
显式 `POWER_OFF` 按键在服务已连接、已认证时，不要求状态回传新鲜或已持有控制权；
网页同样保留此人工掉电入口，并保留管理员校验。状态过期、网络断开或手柄断开
不会自动触发该操作。
按一次只发一次，长按不重复；按键集合必须完全匹配，多余键取消待触发操作。
每条 binding 可配置 `hold_ms`（非负整数，默认 0）：0 表示按下触发；
正值表示整组按键同时保持指定毫秒后触发。提前松开、改变按键集合或输入重新同步均取消计时，
下一次有效按下重新计时。计时使用单调时钟，不阻塞输入和速度刷新，也不依赖按键重复事件。
刚连接、事件队列溢出时的已有按键不作为新按下事件，不重放旧命令。

`trigger: tap` 表示按下后松开时触发一次，不与正数 `hold_ms` 同用。
例如单独 Y 切档、RT+Y 动作：先按 Y 再加 RT 会取消单独 Y 的待触发事件，
松开组合只触发动作，不再补发 Y；先按 RT 再按 Y 同样成立。
LB/RB 单键长按与 LB+RB 并存时，从第二键按下重新计时；组合释放不会补发剩余单键。
组合必须在单键计时到期前凑齐；如果单键已经保持足时，其命令已经发出，不能撤回。

`policy: 策略名` 将绑定限定在指定当前策略。相同按键可在不同策略配置不同操作和时长，
但禁止相同按键的作用范围重叠。切换策略会取消未完成的策略专属按键，保持按住不会自动补发。
通用 FSM、接管等绑定不写 policy，始终适用。策略 ID 只出现在机型 YAML，不写入 common。
`preset` 的 value 支持 slow/fast/toggle；toggle 按服务当前档位切换，不使用客户端旧档位猜测。

`ds4_generic` 的 LT/RT 使用其真实上报的数字按键 310/311，不把扳机轴当成摇杆。
支持 L3/R3、GUIDE、TOUCHPAD；`xbox` 仍只接受该布局已定义的数字按键，未假定其扳机数字上报。
机型可用 `button_codes: {CAPTURE: 317}` 为额外键命名；键码范围和重名会校验，
但配置校验不能证明物理按键有事件。新增硬件键须用原始输入记录或 dry-run 对照。

启动和重连不自动接管；接管前摇杆须居中，获得控制权、进入 RL、切换模式后，
需回中才能重新输出移动速度。失去设备时清零速度、释放控制权，但不请求 POWER_OFF/DAMP。
后台等待设备重新出现；HMI 断开后自动重新连接，仍须手动接管。
静止摇杆没有输入事件，不能据此判断断连。客户端通过 evdev HUP/ENODEV 检测设备断开；
接收器须在无线连接中断时撤销输入设备，不支持断连后继续保留旧轴值的接收器。

速度在 50 Hz 上限下刷新，有效期 300 ms，租约每 250 ms 续期；沿用 HMI 的租约和失联站立行为。
本地请求回执上限 500 ms，单次慢回执不主动断开连接，也不重试状态切换；
速度请求失败后回中重新操作。按键读取先排空积压到最新完整报告，SYN_DROPPED 读取快照清零。
无速度日志刷屏，只记录设备、控制权、状态、组合键结果及首次变化的错误。

速度限额、死区、加减速复用 `operator_service.teleop`，并与当前策略 limits 取交集。
`client_smoothing: false` 的策略已有内部平滑，客户端不叠加一次；其他策略沿用网页同样的线性斜坡。
preset 通过公开 `Client::SetTeleopPreset` 报告成功档位，使音频观察器复用原事件。
模型准备、手臂或舞蹈执行、故障时不发送摇杆非零速度。

可选 `rumble` 配置：`enabled: true`、`backend: ds4_usb`、`device: HIDRAW_BY_ID`、
`duration_ms: 120`、`strength: 90`（强度 1..255，时长 1..500 ms）。只支持已核验
32 字节 0x05 输出的 USB DS4 兼容接口，不将 USB 报告发送给蓝牙接口。
打开时校验与 evdev 属于同一 HID、VID/PID、USB 总线类型和输出报告长度。
包布局依据 Linux `hid-playstation.c` 中的 DualShock4 USB output report，只有 motor 标志有效，
不写灯光、音频、配对或固件配置。设备权限由机型部署环境提供，不自动修改 udev。

仅本客户端发起的 state/policy 请求，在 completed 回执、请求序号和目标状态一致后短震一次。
受理不算成功；失败、重连、启动状态、重复选择当前值、其他客户端操作不震。
USB 写入和定时停止都在独立普通线程，不睡眠阻塞摇杆循环；无权限/不支持只禁用震动。
`--dry-run` 不打开输出设备。

手柄停振会间隔 20 ms 连发三次零振幅，连接时先归零，空闲每秒补发归零。
震动结束使用固定截止时间，期间重复请求合并，不延长震动；所有 USB 写入在独立
反馈线程中执行，不占用机器人控制线程。
断开时只取消当前震动会话，输入循环不等待 USB 写入返回；重连只保留最新设备会话。
同一客户端最多使用一个反馈线程，旧会话结束并归零后才处理新会话，不积累重连线程。
客户端销毁最多等待反馈线程 100 ms；若 USB 仍未返回，线程独立持有其状态完成清理，
不再访问已销毁的客户端对象。

验证入口：

- `hmi_gamepad CONFIG --check-config`：只读解析配置，不连接 HMI 或设备。
- `hmi_gamepad CONFIG --dry-run [--policy NAME]`：只读设备，打印方向和绑定结果，无网络命令。
  默认以策略目录第一项作为输入测试上下文；`--policy` 只影响输入解释，不切真实模型。
- `test_gamepad_input`：归一化、布局、单键/组合长按、点按冲突、策略范围、重连、限速和平滑。
- `test_gamepad_config [CONFIG]`：配置拒绝用例；给 YAML 时逐条回放其声明的实际绑定，不访问设备。
- `test_gamepad_feedback`：成功去重、失败/重连不重放和 USB 报告字段；不访问设备。
- `test_operator_network`：快慢档 API 的控制权约束、参数校验和状态回报。

独立 dry-run 时不要同时运行会响应相同组合键的生产手柄客户端。
设备权限由机型 service 的 input 附加组提供，不能以扩大所有 input 文件权限代替。
